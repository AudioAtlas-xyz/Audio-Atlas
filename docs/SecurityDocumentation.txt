    1. CORS
================================================================================
Criteria: CORS is restricted to the production frontend origin only
Status: Secure

In the Backend/src/AudioAtlasView/Program.cs the allowed origins is specified by a policy named “AllowFrontend”.
This policy calls the method “.WithOrigins(allowedOrigins!)”.
The allowedOrigins throws an exception during startup if the configuration is empty or missing.

The allowed origins are:
Development:
- “http://localhost:3000”
- “http://127.0.0.1:3000”
Specified in appsettings.Development.json.

Production:
- “https://www.audioatlas.xyz”
- “https://audioatlas.xyz”
Specified in appsetting.Production.json

    2. Github, Environments and Secrets
================================================================================
Criteria: Environment variables and connection strings are not exposed in client-side code or git History
Status: Secure
Github
In both github workflows for backend and frontend there is no environment variable used instead it uses secrets via GitHub Action Secrets and Azure in the form of ${{secrets. <SECRET_NAME>}}

In the gitignore file ensures that these are ignored by Git
-.env
-.env. *
-!.env.example
-launchSettings.json
The backend CICD.yml contains a password (“TestPassword123!”), but this is for testing and not for the real database.

Nuxt:
In nuxt.config.ts the application uses runtimeConfig where apiBase and backendBaseURL is public and apiProxyTarget is not public. apiBase and backendBaseURL do not contain secrets and are non-sensitive. There are not hardcoded environments instead it uses process.env.

    3. OAuth tokens and Session Cookies:
================================================================================
Criteria: OAuth tokens and session cookies are configured with secure flags
Status: Secure

Explanation:
The application uses OAuth authentication via GitHub or Google. When signing in with either GitHub or Google there are
temporary cookies which are httponly and secure. The application uses JSON Web Tokens (JWT) once the identity is verified via GitHub or Google.
The bearer token is stored in the Authorization header of the HTTP request that needs authentication.

Note:
To ensure more security during OAuth the temporary cookies should also use SameSite=Lax attribute.

    4. Cross site scripting
================================================================================
Criteria: All user-submitted content (genre names, descriptions, aliases) is sanitized before rendering to prevent XSS (Cross-site scripting attack)
Status: Partially secure


Secure:
Explanation:
Nuxt/Vue automatically escapes HTML content. This prevents the accidentally injecting executable HTML into the application.
In the submission-form page the data from genre names, descriptions and aliases (and the rest of the input) is rendered using double curly braces interpolation e.g. {{ submissionData.NewGenreName }}, to ensure it is handled as a text and not script.
This prevents the application from XSS attacks.

Not secure:
Codacy issues: https://app.codacy.com/gh/AudioAtlas-xyz/Audio-Atlas/dashboard
Severity: high
Explanation: there a two cases of location.href detected via Codacy this can lead to XSS attacks, when assigning user input directly to location.href.
In this case: const loginWithGoogle = () => {window.location.href = loginUrl('google')}.

Detected:
- frontend/app/components/UserFlow/LoginModal.vue line 17
- frontend/app/components/UserFlow/LoginModal.vue line 21

    5. SQL injection
================================================================================
Criteria: All database queries use parameterized queries or EF core (no raw string concatenation)
Status: Secure

Explanation:
The repositories in Backend/src/AudioAtlasInfrastructure/Repositories uses EF Core's parameterized queries.
The repositories retrives instances of the entity classes using Language Integrated Query (LINQ). e.g .Where(), .SingleOrDefaultAsync(), .AddAsync().
EF Core translate this into parameterized SQL commands. This is to prevent SQL injections.

================================================================================
    6. Input validation
================================================================================
Criteria: API endpoints validate input types and reject malformed requests with appropriate error codes
Status: Secure

Explanation:
The application's controllers found in Backend/src/AudioAtlasView/Controllers all use the "[ApiController]" attribute.
This enables automatic model validation and will automatically result in a rejection with a "400 Bad Request", if data is invalid.

The applications uses DTOs found in Backend/src/AudioAtlasApplication/DTO.
In these Data Transfer Objects each field is defined by a specific type e.g. Guid for the IDs and DateOnly for StartDate and EndDate.
This ensures validation of input types and any malformed request will automatically be rejected with a "400 Bad Request".

    7. Cross-Site Request Forgery (Critical)
================================================================================
Codacy issues: https://app.codacy.com/gh/AudioAtlas-xyz/Audio-Atlas/dashboard
Serverity: Critical

Explanation:
Codacy flags the application for failing to protect against CSRF due to not including the '[ValidateAntiForgeryToken]' attribute on an HTTP method handler that could change user state (usually in the form of POST or PUT methods).
The vulnerabillity can be exploited by an adversary creating a link or form on a third party site and tricking an authenticated victim to access them.
This would mean that even though the application validates the input types (6. Input validation) it do not verfiy the authenticity of the requst source.
Therefore the risk is that an attacker can trick an authenticated user into submitting unwanted requests.
However the application uses JWT Bearer tokens (as explained in section 3) on the client side. This means that the authentication tokens gets send manually by the Nuxt code.
Therefore it is secure against CSRF, because the browser dont attach the authentication header to cross site request.

Detected in:
- Backend/src/AudioAtlasView/Controllers/SubmissionsController.cs line 60
- Backend/src/AudioAtlasView/Controllers/CountriesController.cs line 60
- Backend/src/AudioAtlasView/Controllers/GenresController.cs line 42

Recommended fixes:
- Add the [ValidateAntiForgeryToken] attribute to all HTTP methods where this issue is detected.
- Or add a global fix with a AutoValidateAntiforgeryTokenAttribute filter in the program.cs file
- To enhance protection session cookies should be set with the SameSite=Lax attribute.
